# 모니터링 운영 런북

## 1. 목적

이 문서는 모니터링 스택에서 자주 발생한 장애를 빠르게 진단/복구하기 위한 운영 절차를 정리한다.

적용 범위:

- Grafana
- Prometheus
- node-exporter
- kube-state-metrics
- ingress-nginx metrics 연동

---

## 2. 공통 점검 순서

1. 파드 상태 확인

```bash
kubectl -n manufacturing-monitoring get pods -o wide
```

2. Prometheus targets 확인

```bash
kubectl -n manufacturing-monitoring exec deploy/prometheus -- \
  sh -c 'wget -qO- http://127.0.0.1:9090/prometheus/api/v1/targets'
```

3. Grafana 로그 확인

```bash
kubectl -n manufacturing-monitoring logs deploy/grafana --tail=200
```

---

## 3. 장애 유형별 대응

### 3.1 Grafana 패널 404 (Prometheus 쿼리 실패)

증상:

- Grafana 패널에서 `Status: 404 page not found`

원인 후보:

- Prometheus가 `/prometheus` route-prefix로 실행 중인데 datasource URL이 `http://prometheus:9090`로 설정됨

복구:

1. datasource URL 확인
   - `http://prometheus:9090/prometheus` 이어야 함
2. Grafana 이미지 새 태그 빌드/푸시
3. Deployment 이미지 태그 갱신 및 롤아웃

검증:

```bash
kubectl -n manufacturing-monitoring exec deploy/grafana -- \
  sh -c 'wget -qSO- http://prometheus:9090/prometheus/api/v1/query?query=up 2>&1 | head -n 5'
```

---

### 3.2 Prometheus CrashLoopBackOff (storage lock)

증상:

- `opening storage failed: lock DB directory: resource temporarily unavailable`

원인:

- 단일 PVC를 쓰는 Prometheus에서 롤링 업데이트 중 신구 파드가 동시에 떠서 lock 충돌

복구:

1. `prometheus` Deployment 전략을 `Recreate`로 설정
2. 실패 파드 삭제
3. 롤아웃 상태 확인

검증:

```bash
kubectl -n manufacturing-monitoring rollout status deployment/prometheus --timeout=240s
```

---

### 3.3 대시보드 수정이 반영되지 않음

증상:

- JSON 파일 수정 후에도 Grafana 화면이 이전 상태

원인:

- 동일 이미지 태그 재사용 + `imagePullPolicy: IfNotPresent`로 노드 캐시 재사용

복구:

1. 이미지 태그 증가 (예: `3.2` -> `3.3`)
2. 새 이미지 빌드/푸시
3. Deployment 이미지 태그 변경 후 롤아웃

검증:

```bash
kubectl -n manufacturing-monitoring exec deploy/grafana -- \
  sh -c 'grep -R "원하는 쿼리 문자열" /etc/grafana/provisioning || true'
```

---

### 3.4 SQL 대시보드 에러 (DB 접속 실패)

증상:

- PostgreSQL datasource 패널에서 500/연결 실패

원인 후보:

- datasource host 불일치
- Grafana Pod에 DB 접속 env 미주입
- NetworkPolicy에서 Grafana -> postgres 5432 미허용

복구:

1. datasource host를 K8s 서비스 DNS로 수정
2. Grafana Deployment env 주입 확인
3. app namespace DB 정책에 Grafana 허용 규칙 추가

검증:

- Grafana datasource `Save & Test` 성공
- SQL 패널 에러 0건

---

## 4. 운영 체크리스트

- 배포 전
  - 이미지 불변 태그 증가 여부 확인
  - Prometheus config 변경 시 self-scrape 경로 확인
  - NetworkPolicy 변경 diff 확인

- 배포 후
  - `kubectl -n manufacturing-monitoring get pods`
  - Prometheus targets에서 핵심 jobs health=up 확인
  - Grafana 대시보드 주요 패널 1회 수동 확인

---

## 5. 표준 복구 명령 모음

```bash
# Grafana 재시작
kubectl -n manufacturing-monitoring rollout restart deployment/grafana

# Prometheus 재시작
kubectl -n manufacturing-monitoring rollout restart deployment/prometheus

# rollout 상태 확인
kubectl -n manufacturing-monitoring rollout status deployment/grafana --timeout=240s
kubectl -n manufacturing-monitoring rollout status deployment/prometheus --timeout=240s
```
